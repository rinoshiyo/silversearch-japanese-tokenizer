# Silversearch Japanese Tokenizer

日本語 | [English](README.en.md)

[SilverBullet](https://silverbullet.md/)の全文検索プラグイン[Silversearch](https://github.com/MrMugame/silversearch)で、日本語を検索できるようにするtokenizer（検索のために文章を区切る部品）です。

日本語は単語の間に空白が無いため、Silversearchの標準の区切り方では、文の途中にある語を検索できません。このtokenizerは、日本語の文字（漢字・ひらがな・カタカナ）の連なりを2文字ずつ重ねて区切ります。多くの全文検索エンジンが日本語・中国語・韓国語に使う、bi-gramと呼ばれる方式です。

```
東京リージョン -> 東京 / 京リ / リー / ージ / ジョ / ョン
```

検索語も同じように区切るので、`リージョン`で検索すると`東京リージョン`を含むページが見つかります。辞書を使わず、ほかのライブラリへの依存もありません。

- 全角と半角を区別しません（UnicodeのNFKC正規化）。`ＥＣ２`で`EC2`が見つかり、その逆も見つかります。`ﾐｶﾝ`で`ミカン`が見つかります
- 々 〆 〇 ヶ ゝ ゞ ー と、𠮷 のような拡張漢字も日本語の文字として扱います
- 句読点と記号で区切ります。`、。・「」（）【】〜`と半角の記号が対象です
- 日本語の文字に挟まれたMarkdownの記号では区切りません。`**重要**な話`は`重要な話`で、`[[会議メモ]]を見る`は`会議メモを見る`で見つかります
- 英語などの日本語以外の文章は、これまでどおりに区切ります

## 入れ方

Library Managerで **Install from URI** を選び、次を入力します。

```
github:rinoshiyo/silversearch-japanese-tokenizer/PLUG.md
```

次に、SilverBulletの設定のページ（`CONFIG`など）に以下を書き足し、`Silversearch: Reindex`を実行します。

```lua
config.set("silversearch.tokenizers", {
  ["Library/rinoshiyo/silversearch-japanese-tokenizer.js"] = {}
})
```

## オプション

オプションは、入れ方の手順で書き足した`config.set`の中で、tokenizerのファイル名の後ろの`{}`に書きます。何も書かなければ、すべて既定値で動きます。

| オプション | 既定値 | 内容 |
|---|---|---|
| `indexLastCharacter` | `false` | 日本語の連なりの最後の1文字を、1文字だけの区切りとしても索引に入れる |

```lua
config.set("silversearch.tokenizers", {
  ["Library/rinoshiyo/silversearch-japanese-tokenizer.js"] = {
    indexLastCharacter = true,
  }
})
```

オプションを変えたら、`Silversearch: Reindex`を実行してください。索引に入る語が変わるためです。

### indexLastCharacter

1文字で検索することが多いなら`true`、普段の検索の見た目を優先するなら`false`のままにしてください。`true`にすると、1文字で検索した時の取りこぼしがなくなります。代わりに、2文字以上で検索するたびに、強調表示が余計に付きます。

**1文字の検索**: Silversearchは検索語を前方一致で照合します。既定では、連なりの途中の文字は、その文字で始まる2文字の区切りに当たるので見つかります。連なりの最後の文字には、その文字で始まる区切りが無いため見つかりません。`true`にすると、最後の1文字も区切りとして索引に入るので見つかります。

| 本文 | 検索語 | `false`（既定） | `true` |
|---|---|---|---|
| `税金の支払い` | `税` | 見つかる | 見つかる |
| `消費税。` | `税` | 見つからない | 見つかる |

**副作用（強調表示）**: 検索語も同じ規則で区切られるため、`true`では検索語の最後の1文字が区切りに加わります。Silversearchはこの1文字にも前方一致で照合し、その文字で始まる語をページ中から探して強調します。見つかるページは変わらず、強調の付き方だけが変わります。

| 本文 | 検索語 | `false`（既定） | `true` |
|---|---|---|---|
| `インスタンスを東京リージョンで建てた` | `リージョン` | `リージョ`だけ強調 | `リージョン`に加え、`インスタンス`の`ンス`も強調 |

## 索引の作り直し（Reindex）

Silversearchは索引をブラウザごとに持っています。そのため`Silversearch: Reindex`は、使っている端末とブラウザのそれぞれで実行してください。このtokenizerを更新した時やオプションを変えた時も、同じく端末ごとに実行し直します。その後に作ったり書き換えたりしたページは、自動で索引されます。

## 既知の制約

bi-gramの方式とSilversearch本体の仕様によるものです。いずれもテストで挙動を確かめています。

- 空白を入れずにつなげた複合語は、本文の側で間に別の文字が入っていると見つかりません。`請求書送付`では`請求書を送付した`が見つかりません。`請求書 送付`と空白で区切って検索してください
- 長い語の一部にも当たります（`京都`で`東京都`が見つかります）。検索語の2文字の組がページ内にすべてそろっていれば、並びが違っても当たります（`インスタンス`で`インスタント`が見つかります。どちらも`イン`・`ンス`・`スタ`・`タン`を含むためです）。引用符で囲む（`"インスタンス"`）と、その並びのとおりに含むページだけに絞れます
- 長音の有無、ひらがなとカタカナ、旧字体・異体字は区別します。`サーバー`で`サーバ`は見つからず、`リンゴ`で`りんご`は見つからず、`高橋`で`髙橋`は見つかりません
- 日本語の連なりの最後の1文字は、`indexLastCharacter`を有効にしない限り、1文字だけの検索では見つかりません（[オプション](#オプション)を参照）
- Silversearch 1.2.5は、区切る前に、本文と検索語の両方から半角の濁点・半濁点・長音（`ﾞ ﾟ ｰ`）を取り除きます。そのため、これらを含む半角カナは見つかりません（`ﾊﾟｿｺﾝ`と`パソコン`は互いに見つかりません）。Silversearch側の修正が必要です。当面の回避策として、Silversearchのオプション`ignoreDiacritics`を`false`にすると、半角カナの検索語で全角の本文が見つかるようになります。ただし、半角カナで書いた本文は見つからないままです。欧文のアクセントも区別するようになります（`cafe`で`café`が見つからなくなります）
- 引用符で囲んだ検索と強調表示は、本文の文字そのままと比べるため、全角と半角を区別します（`"EC2"`で`ＥＣ２`は見つからず、`EC2`で検索しても`ＥＣ２`は強調されません）
- 文字数が奇数の検索語は、最後の1文字が強調されないことがあります（`リージョン`は`リージョ`まで強調されます）。Silversearchが重なり合う一致を飛ばして強調するためです。ページ自体は見つかります

## 開発

tokenizerはTypeScript（`src/`）で書き、1つのファイル`silversearch-japanese-tokenizer.js`にビルドしています。Library Managerから入れられるよう、ビルドしたファイルもリポジトリに含めました。

```shell
npm ci
npm test   # 型チェック、ビルド、テスト
```

`silversearch-japanese-tokenizer.js`を変えたら、版の番号も上げてください。版は`package.json`・`PLUG.md`・`src/silversearch-japanese-tokenizer.ts`の冒頭の3か所にあり、テストで一致を確かめています。Library Managerの更新は`PLUG.md`の中身だけを比べるため、版を上げずに`.js`だけを変えると、利用者が更新しても新しい`.js`が届きません。

テストは、Silversearch 1.2.5の索引と検索の処理にtokenizerを通して確かめます。Silversearchのソースは、テストの前にGitHubから取得します（SilversearchはGPL-3.0のため、このリポジトリには含めていません）。
